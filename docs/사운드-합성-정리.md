# 사운드 정리 — 합성음 + 녹음 샘플 하이브리드

> 질문: **"지금 사운드가 js 파일로 되어 있나? mp3 이런 게 아니고?"**
> 답: **원래는 100% 합성이었고, 지금은 둘을 섞어 씁니다.** 효과음 11종은 여전히
> `src/audio.js` 안에서 **실시간으로 계산해서** 만들고, 가장 자주 듣는
> **화염구·서리 폭발**은 녹음 샘플(wav), **배경음악**은 곡 파일(mp3)을 씁니다.
> 파일을 못 읽으면 자동으로 예전 합성음·합성 드론이 나오므로 소리가 사라지지 않습니다.

프로젝트 전체 오디오 파일:

```
$ ls assets/sound
bgm.mp3                        3.0MB  219.1초   ← 배경음악 (겹쳐 이어 붙여 무한 반복)
fireball.wav                    52KB    0.55초   ← 화염구
frost.wav                       84KB    0.90초   ← 서리 폭발
source/                        376KB            ← 효과음 원본 (다듬기 전)
source/music/                  4.1MB            ← 배경음악 원본 mp4 (.gitignore, 인코딩용)
```

**왜 이 셋만 파일인가** — 합성음은 "게임보이"스러운 톤이 한계입니다. 가장 많이 듣는
주력기 두 개와, 애초에 합성으로는 곡이 될 수 없는 배경음악만 파일로 올렸습니다.
나머지 11종은 짧은 타격·UI 음이라 합성으로 충분하고, 그 편이 용량과 관리가 편합니다.

## 1. 녹음 재생 vs 합성 — 뭐가 다른가

| | **파일 재생** (일반적인 방식) | **합성** (이 게임의 방식) |
|---|---|---|
| 소리의 출처 | 미리 녹음/제작된 mp3 파형을 읽어 재생 | 발사 순간에 파형을 **수식으로 만들어** 스피커로 보냄 |
| 필요한 것 | `sfx/fire.mp3`, `bgm.mp3` … 파일들 | 코드 한 파일 |
| 용량 | 효과음 13개 + 배경음 → 보통 2~10MB | **0 바이트** (audio.js 5KB에 포함) |
| API | `<audio>` 또는 `AudioBufferSourceNode` | **Web Audio API** 노드 그래프 |
| 장점 | 원하는 소리를 정확히 넣을 수 있음, 퀄리티 상한이 높음 | 파일 관리·로딩·저작권 문제가 없고, 매번 미세하게 다른 소리를 낼 수 있음 |
| 단점 | 에셋 준비·용량·라이선스 | 사람 목소리, 실제 악기 같은 복잡한 소리는 못 만듦. "게임보이스러운" 톤이 됨 |

이 게임은 **에셋 0개로 굴러가는 것**을 기본값으로 잡고 합성으로 시작했습니다
(텍스처도 `world.js` 에서 캔버스로 그려 씁니다). 그 위에 **가장 많이 듣는 소리
두 개만** 파일 재생으로 올린 게 지금 상태입니다 — 표의 두 칸을 고르는 문제가 아니라,
합성을 바닥에 깔고 필요한 곳만 샘플로 덮는 쪽이 실제로는 가장 싸게 먹힙니다.
샘플이 없으면 합성음이 그대로 나오므로 파일이 빠져도 게임은 조용해지지 않습니다.

## 2. Web Audio API 용어

브라우저에 내장된 신디사이저라고 보면 됩니다. **노드(부품)를 연결해 그래프를 만들면**
그 경로를 따라 소리가 흘러 스피커로 나갑니다.

| 용어 | 뜻 | 이 게임에서 |
|---|---|---|
| **AudioContext** | 오디오 엔진 전체. 모든 노드를 여기서 만듦 | `this.ctx`, 게임 시작 시 1개 생성 |
| **destination** | 그래프의 끝 = 스피커 | `master.connect(ctx.destination)` |
| **GainNode** | 볼륨 조절기 | 마스터 볼륨(0.5), 각 소리의 엔벨로프, 음소거 |
| **OscillatorNode** | 순수한 파형 발생기 (사인/사각/톱니/삼각) | `_tone()` 의 재료 |
| **AudioBuffer / BufferSourceNode** | 메모리에 든 샘플 데이터를 재생 | **화이트 노이즈 2초치**를 만들어 루프 재생 |
| **BiquadFilterNode** | 주파수 필터 (lowpass/highpass/bandpass) | 노이즈를 "쉬익", "쾅", "치직"으로 깎아내는 핵심 |
| **currentTime** | 오디오 엔진의 시계(초). `Date.now()` 보다 정밀 | 모든 예약의 기준점 `get t()` |
| **setValueAtTime / exponentialRampToValueAtTime** | "언제 이 값, 언제까지 이 값으로 미끄러져라"고 **미리 예약** | 음정 하강, 볼륨 감쇠 |
| **엔벨로프 (ADSR)** | 소리의 시간에 따른 음량 곡선 (어택-디케이-서스테인-릴리스) | 12ms에 최대 → 지수적으로 감쇠 (타악기형) |
| **LFO** | 귀에 안 들릴 만큼 느린 오실레이터. 다른 값을 흔드는 용도 | 배경 드론의 미세한 흔들림 (0.05~0.11Hz) |
| **detune** | 음정을 센트 단위로 미세 조정 | LFO가 여기를 흔들어 코러스 효과 |
| **화이트 노이즈** | 모든 주파수가 고르게 섞인 잡음 = "쉬익" | 폭발·타격·번개의 몸통 |

> ⚠️ `exponentialRampToValueAtTime` 은 **0으로 갈 수 없습니다** (지수 곡선이라 0을 못 지남).
> 그래서 코드에 `0.0001`, `0.0008` 같은 어정쩡한 최소값이 보이는 것입니다. 실질적 무음.

## 3. 신호 흐름

```
[_tone]  Oscillator ──┐
         (음정 하강)   │
                      ├──► Gain (엔벨로프) ──┐
[_noise] BufferSource │                      │
         (노이즈 루프) └► BiquadFilter ──────┤
                          (컷오프 스윕)       │
                                             ├──► master Gain (0.5) ──► destination
[startPad] Osc×3 ──► Lowpass(380Hz) ──► Gain │        ▲                    (스피커)
            ▲                          (0.055)        │
            └── LFO ──► detune                   M 키 → 0 (음소거)
```

소리 하나를 낼 때마다 **노드를 새로 만들고 → 연결하고 → 예약 재생하고 → 스스로 끝나면 버립니다.**
(`o.stop(t + dur)` 로 정지 예약까지 걸어두면 GC가 알아서 수거합니다.)

## 4. 재료는 딱 두 개

### `_tone(f0, f1, dur, opts)` — 음정이 있는 소리

`f0` Hz에서 시작해 `dur` 초 동안 `f1` Hz로 **미끄러지는** 오실레이터.

- `type` — `sine`(둥글고 순함) / `triangle`(살짝 밝음) / `sawtooth`(거칠고 꽉 참) / `square`(전자음)
- 볼륨은 12ms만에 최대치로 올라갔다가 `dur` 동안 지수 감쇠 → **때리는 느낌**
- `delay` 로 시작 시점을 밀 수 있음 → 아르페지오(도-미-솔)에 사용

### `_noise(dur, opts)` — 음정이 없는 소리

2초짜리 화이트 노이즈를 루프로 틀고, **필터로 깎아서** 성격을 만듭니다.

- `lowpass` + 컷오프를 2600Hz → 400Hz로 하강 = **"쉬이익…" 사그라드는 폭발**
- `highpass` + 컷오프를 900Hz → 4200Hz로 상승 = **"차르르" 얼어붙는 서리**
- `bandpass` + 높은 Q = **"치직" 좁은 대역만 남은 전기**

거의 모든 효과음이 **_tone(몸통) + _noise(질감)** 두 겹으로 되어 있습니다.

## 5. 효과음 13종 레시피

| 이름 | 언제 | 구성 | 노린 것 |
|---|---|---|---|
| `fire` | 화염구 발사 | **fireball.wav** (실패 시 톱니 620→180Hz + 저역 노이즈) | 훅 뿜는 화염 |
| `boom` | 화염구 폭발 | 노이즈 1400→60Hz + 사인 140→40Hz | 저음이 배를 치는 폭발 |
| `frost` | 서리 폭발 | **frost.wav** (실패 시 삼각 1500→420Hz + 고역 상승 노이즈) | 쨍하게 얼어붙는 느낌 |
| `zap` | 연쇄 번개 | bandpass 노이즈(Q 2.5) + 사각 2200→300Hz | 짧고 날카로운 방전 |
| `meteor` | 메테오 | 톱니 90→30Hz + 노이즈 1.1초 + **fireball.wav 절반 속도** | 길고 무겁게 낙하 |
| `blink` | 점멸 | 사인 300→**1600Hz(상승)** + 고역 노이즈 | 위로 빨려 들어가는 순간이동 |
| `hit` | 적 피격 | 노이즈 0.08초 | 짧은 타격감 |
| `death` | 적 사망 | 사각 360→70Hz + 노이즈 | 푹 꺼지는 소리 |
| `hurt` | 플레이어 피격 | 톱니 220→80Hz | 둔탁하고 불쾌하게 |
| `levelup` | 레벨업 | **도-미-솔-도** (523·659·784·1046Hz) 90ms 간격 | 상승 아르페지오 = 보상감 |
| `wave` | 웨이브 시작 | 낮은 3화음(196·262·330Hz) 톱니 | 경고 팡파르 |
| `nomana` | 마나 부족 | 사각 200→150Hz, 0.12초 | 짧은 거절음 |
| `pickup` | 경험치 획득 | 삼각 880→1320Hz | 가볍게 위로 튀는 소리 |

> **상승 = 좋은 일, 하강 = 나쁜 일** 이라는 규칙을 지켰습니다.
> `pickup`·`levelup`·`blink` 만 음정이 올라가고 나머지는 전부 내려갑니다.

호출부는 `spells.js`(마법 8곳)와 `main.js`(피격·사망·웨이브·레벨업 등 6곳)에 흩어져 있고,
전부 `audio.play('이름')` 한 줄입니다.

## 6. 배경음 — 곡(`bgm.mp3`) + 합성 드론(`startPad`)

### 지금 깔리는 것: 3분 39초짜리 한 곡

`assets/sound/bgm.mp3` (Varco Sound 로 만든 룬가드 테마) 를 계속 돌립니다.
재생 게인이 0.28, 마스터가 0.5 이므로 스피커로 나가는 건 곡 자체보다 훨씬 작아서
마법 소리를 가리지 않습니다. 곡을 갈아끼울 때는 **인코딩 단계에서 평균 레벨을
맞춰 두는 쪽**을 택했습니다 — 게인 상수를 곡마다 다시 고르지 않아도 됩니다.

**① 4.1MB mp4 를 3.0MB mp3 로** — 원본은 Varco Sound 가 내준 mp4(영상 + AAC
48kHz 스테레오)입니다. 게임이 필요한 건 소리뿐이라 `tools/build-bgm.mjs` 가
ffmpeg 으로 영상 트랙을 버리고 112kbps mp3 로 굽습니다. 같은 스크립트에서
`volume=-1.3dB` 를 먹여 예전 곡(-16.7dB)과 같은 평균 레벨(-17.1dB)로 맞춥니다.

**② 이음매** — 곡 끝이 자연스럽게 잦아드는 아웃트로이고 인트로도 조용히 쌓아
올리는 곡이라, 끝까지 재생하고 다시 트는 흔한 방식(`loop = true`)이면 매 바퀴마다
소리가 푹 꺼졌다 돌아옵니다. 그래서 **아웃트로가 시작될 즈음 다음 바퀴를 미리 틀어
겹칩니다** — 꺼져 가는 꼬리 밑에서 새 인트로가 올라오므로 이음매가 안 들립니다.

겹치는 양(`overlap`)은 꼬리 N초와 머리 N초를 실제로 더해서 평균 레벨을 재 골랐습니다.
곡 전체 평균이 **-17.1dB** 이므로, 이음매가 여기에 가장 가까운 값이 정답입니다.

| overlap | 이음매 평균 | 피크 | 판정 |
|---|---|---|---|
| 0초 (그냥 반복) | -23.9dB | — | 이음매가 6.8dB 푹 꺼짐 |
| 5초 | -18.7dB | -4.6dBFS | 아직 꺼짐이 남음 |
| 7초 | -18.7dB | -3.4dBFS | 좀 낫지만 여전히 1.6dB 낮음 |
| **9초** | **-17.5dB** | **-3.2dBFS** | 곡 평균과 사실상 같음 |
| 11초 | -15.8dB | -2.2dBFS | 이번엔 반대로 이음매만 부풀어 오름 |

예약은 **오디오 시계(`currentTime`) 기준 절대 시각**으로 잡고, 다음 바퀴를 1초 앞서
`setTimeout` 으로 걸어 둡니다. 타이머가 밀려도 이음매는 밀리지 않습니다.

### 곡이 없을 때: 끝나지 않는 드론

곡을 못 읽었을 때, 그리고 곡이 디코드되기까지의 짧은 사이를 메우는 폴백입니다.

1. **저음 드론 3개** — 55 / 82.5 / 110Hz (A1 + 5도 + A2). 톱니 2개 + 삼각 1개
2. 각각에 **아주 느린 LFO**(0.05·0.08·0.11Hz)를 `detune` 에 연결 → 서로 어긋나며 흔들려
   기계적이지 않고 살아있는 소리가 됨
3. **lowpass 380Hz** 로 위를 잘라내 웅웅거리는 저음만 남김
4. 그 위에 **1.5초마다 한 음씩** 아르페지오 (A-C-E-G-E-C, 볼륨 0.035) → 음산한 분위기

곡이 준비되면 `stopPad(1.5)` 로 드론을 1.5초에 걸쳐 내리고 자리를 넘깁니다.
드론과 곡은 조성이 안 맞아 같이 울리면 탁해지기 때문에 **겹치지 않고 교대**시킵니다.

## 7. 알아둘 만한 구현 포인트

**① 브라우저 자동재생 정책**
AudioContext 는 사용자 조작 없이 시작하면 `suspended` 상태로 잠깁니다.
그래서 `ctx` 생성을 **"시작" 버튼을 누르는 `startRun()` 시점**(`main.js:180`)까지 미룹니다.
재시작 시에는 이미 만든 컨텍스트를 `resume()` 만 합니다.

**② 음소거 (`M` 키)**
개별 소리를 끄는 게 아니라 **마스터 게인 하나를 0으로** 내립니다 (`main.js:380`).
`play()` 는 `muted` 면 노드 생성 자체를 건너뛰므로 음소거 중엔 연산도 안 합니다.

**③ 소리마다 노드를 새로 만든다**
Web Audio 의 소스 노드는 **일회용**입니다 (`start()` 한 번, `stop()` 하면 끝).
재사용하려 하면 에러가 나므로, 발사할 때마다 새로 만드는 게 정상적인 사용법입니다.

## 8. 녹음 샘플을 섞은 방법

`audio.js` 의 인터페이스가 `start()` / `play(name)` / `toggleMute()` 세 개뿐이라
**호출부(`spells.js`·`main.js`)는 한 줄도 안 고치고** 내부만 갈아끼웠습니다.

### ① 원본을 그대로 쓰면 안 되는 이유

받은 wav 는 앞뒤로 무음과 긴 페이드가 붙은 "감상용" 길이였습니다.

```
Fireball_launch_1.wav  2.33초 — 0.00~0.75초가 서서히 부푸는 예열 구간
Ice_spell_2.wav        1.67초 — 0.00~0.20초가 도입부, 1.10초 이후는 거의 무음
```

이대로 붙이면 두 가지가 깨집니다.

- **반응이 늦다** — 클릭하고 0.75초 뒤에 소리가 나면 마법이 "느리게" 느껴집니다.
  게임 효과음은 트리거 순간에 이미 최대음량이어야 합니다.
- **연사하면 뭉갠다** — 화염구 쿨다운은 0.4초인데 소리는 2.3초짜리라, 계속 쏘면
  6겹까지 겹쳐 저역이 뭉치고 음량이 치솟습니다.

### ② `tools/build-sfx.mjs` — 자르고 다듬기 (의존성 없는 Node 스크립트)

```
node tools/build-sfx.mjs --scan   # 25ms 단위 엔벨로프를 찍어 자를 구간을 고른다
node tools/build-sfx.mjs          # source/*.wav → 게임용 wav
```

| 단계 | 하는 일 | 왜 |
|---|---|---|
| 구간 자르기 | fireball 0.76~1.31초, frost 0.20~1.10초만 남김 | 트리거 즉시 최대음량 + 쿨다운 안에 끝나게 |
| DC 오프셋 제거 | 파형 평균(±0.001)을 0으로 | 겹쳐 재생할 때 오프셋이 쌓여 헤드룸을 먹음 |
| 페이드 | 인 4~5ms, 아웃 0.25~0.30초(raised-cosine) | 잘린 단면이 만드는 "딱" 소리 방지 + 꼬리 정리 |
| 피크 정규화 | -1.5 dBFS (0.84) | 두 파일의 기준 음량을 맞춤 |

결과: **219KB 2.33초 → 52KB 0.55초**, **157KB 1.67초 → 84KB 0.90초**.

### ③ 로딩 — 다운로드와 디코드를 분리

`AudioContext` 는 사용자 조작 전에 만들 수 없지만 **다운로드는 미리 할 수 있습니다.**
그래서 `Audio` 생성자에서 `fetch` 만 걸어 두고(로딩 화면 동안 끝남),
`decodeAudioData` 는 컨텍스트가 생기는 `start()` 로 미룹니다.

```js
const SFX = {
  fire:  { file: 'fireball.wav', gain: 0.26, rate: [0.93, 1.09] },
  frost: { file: 'frost.wav',    gain: 0.40, rate: [0.97, 1.04] }
};

play(name) {
  switch (name) {
    case 'fire': if (this._sample('fire', { gain: SFX.fire.gain })) break;
                 /* 샘플이 없으면 아래 합성음으로 그대로 진행 */
                 this._tone(620, 180, 0.22, ...);
  }
}
```

`_sample()` 은 버퍼가 준비되지 않았으면 `false` 를 돌려주고, 호출부는 곧바로
합성음으로 넘어갑니다. 그래서 **로딩 중 첫 발**이나 `file://` 로 연 경우에도
소리가 비지 않습니다.

### ④ 두 가지 잔손질

- **피치 흔들기** — 재생마다 `playbackRate` 를 0.93~1.09 사이에서 뽑습니다.
  똑같은 파형이 초당 2~3회 반복되면 기계적으로 들리는데, 이 한 줄로 사라집니다.
- **음량 맞추기** — 샘플은 합성음과 달리 소리가 꽉 차 있어서, 피크를 맞추면
  체감상 훨씬 큽니다. 마스터 뒤에서 RMS 를 재서 합성 폭발음(`boom`)과
  비슷해지는 지점(`fire` 0.26, `frost` 0.40)까지 내렸습니다.
- **메테오 재활용** — 같은 화염구 샘플을 `playbackRate` 0.5~0.58 로 늦춰
  기존 합성 굉음 위에 겹쳤습니다. 파일 추가 없이 덩치만 키우는 방법입니다.

## 9. 현재의 한계 (고치려면 여기)

| 항목 | 지금 | 개선안 |
|---|---|---|
| 동시 발음 수 | 제한 없음. 적이 몰리면 `hit` 이 수십 개 겹쳐 지저분해짐 | 같은 소리는 30ms 이내 재발음 무시(쿨다운) |
| 위치감 | 전부 모노. 왼쪽에서 터져도 가운데서 들림 | `PannerNode` 또는 `StereoPannerNode` 로 x좌표 반영 |
| 아르페지오 타이밍 | `setInterval` 기반이라 프레임 끊길 때 밀림 | 오디오 시계(`currentTime`) 기준 스케줄러로 예약 |
| 배경음 정리 | `_arp` 인터벌과 드론이 게임 종료 후에도 계속 돎 | `stop()` 메서드에서 `clearInterval` + 오실레이터 정지 |
| 볼륨 조절 | `M` 로 껐다 켜기만 됨 | 마스터 게인에 슬라이더 연결 |
